# 设备命令下发解决方案设计（读属性 / 写属性 / 功能调用）

> 集群发送（多节点部署）的通用集群设施见 [集群管理设计](./集群管理设计.md)。本文档为单机核心设计，集群只是按配置替换发送器实现。

## 一、背景与现状

管理端需要向设备下发三类命令：**读取属性、写入属性、调用功能**。设备收到指令后需回复（MQTT 协议约定 10s 超时，见 [MQTT协议文档](./MQTT协议文档.md)）。

平台部署形态：**单机或集群**（集群时设备随机接入任一节点，会话为本地状态，下发的核心问题：**目标设备的会话可能不在当前节点**，需要集群转发 — 见集群设计文档）。

### 1.1 当前已具备的能力

| 能力 | 位置 | 说明 |
|------|------|------|
| 下行消息类 | `common/message/ReadPropertyMessage`、`WritePropertyMessage`、`FunctionInvokeMessage` | 均实现 `RepayableDeviceMessage<R>`（含 `newReply()` 回复骨架） |
| 回复消息类 | `ReadPropertyMessageReply`、`WritePropertyMessageReply`、`FunctionInvokeMessageReply` | 继承 `AbstractDeviceMessageReply`（success/code/message） |
| 下行 Topic 编码 | `common/topic/TopicMessageCodec` 枚举 | `readProperty`/`writeProperty`/`functionInvoke` 的 `:param` pattern 已定义；`buildTopicSegments()` 自动回填 productKey/deviceKey；子设备枚举递归拼接 `child` topic；入口 `TopicMessageCodec.encode(message) → TopicPayload(topic+payload)` |
| 协议编码器 | `sa-protocol/MqttDeviceMessageCodec.encode()` | Message → `DefaultMqttEncodedMessage`（QoS1），薄封装委托 TopicMessageCodec |
| 连接发送 | `VertxMqttConnection.sendMessage()` | `endpoint.publish()` 异步回调转 Mono，已实现 |
| 会话体系 | `MqttConnectionSession`（持有 connection + 烧录 key）、`ChildDeviceSession`（持有 parent + childKey） | `DeviceSessionManager.getSession(deviceId)` / `getSession(productKey, deviceKey)` / `getSession(deviceId, unregisterWhenNotAlive)`；`listenEvent()` 可监听会话注册/注销 |
| 网关管理 | `DeviceGatewayManager.getGateway(id)` | `MqttServerDeviceGateway` 持有 `Mono<ProtocolSupport>` |
| HTTP 入口 | `DeviceController` | `/device/{deviceId}/properties/read`、`/device/setting/{deviceId}/property`、`/device/invoked/{deviceId}/function/{functionId}` 三个接口已存在 |
| headers 约定 | [平台统一设备消息定义文档](./平台统一设备消息定义文档.md) | `async`（异步下发）、`timeout`（毫秒）已定义 |
| 物模型 | `ThingsMetadata.getPropertyOrNull/getFunctionOrNull`、`PropertyMetadata`（accessMode）、`FunctionMetadata`（inputs/isAsync/output）、`DataType.validate()` | 可用于下发参数校验 |
| 连接服务器 ID | `DeviceField.CONNECTION_SERVER_ID` + `DeviceInfo.connectionServerId` + `DefaultDeviceOperator.getConnectionServerId()` | 字段/读写方法已定义，**当前无写入方**（恒为 null）——集群部署需补会话监听写入（见 [集群管理设计](./集群管理设计.md)） |

### 1.2 当前缺口

| 缺口 | 现状 |
|------|------|
| 会话无发送能力 | `DeviceSession.send(EncodedMessage)` 是注释掉的预留 |
| 无统一下发入口 | `DeviceMessageSender` 不存在，业务层无法对设备发消息 |
| 业务层是桩 | `DeviceService.readProperties/writeProperties/invokeFunction` 均为 TODO 空实现 |
| 回复未处理 | `DefaultDecodedClientMessageHandler.handle()` 对 `MessageReply`/`ChildDeviceMessage` 是 TODO |
| 无超时等待机制 | 缺少 messageId → 回复的 pending 注册表 |
| 无物模型校验 | 写属性/功能调用的参数未按物模型校验与类型转换 |
| 子设备下行未打通 | 子设备命令需包装 `ChildDeviceMessage` 走网关代理，无实现 |
| 集群路由发送缺失 | `ClusterDeviceMessageSender` 不存在（通用集群设施见 [集群管理设计](./集群管理设计.md)） |

## 二、总体设计

### 2.1 分层架构

```
HTTP API（DeviceController 已有接口）
  │
  ▼
DeviceService（实现三个 TODO 方法 + 物模型校验）          ← sa-admin 业务层
  │ 注入 DeviceMessageSender 接口（不感知本地/集群）
  ▼
DeviceMessageSender（接口）                              ← sa-base 下发抽象
  ├── LocalDeviceMessageSender        — 本地实现（本节点会话直接下发）【本文档】
  └── ClusterDeviceMessageSender      — 集群路由实现（持有 ClusterManager：
        ① 取设备所在节点（Redis CONNECTION_SERVER_ID）
        ② 本地节点 → 直接走本地发送
        ③ 远程节点 → clusterManager.getService(nodeId, DeviceMessageSender)
                     返回远程代理，代理经 Hazelcast 转发到目标节点执行）【见集群管理设计】
  ▼
LocalDeviceMessageSender（设备所在节点执行）
  │  ① 查会话 + 在线判定（离线 → 报错）
  │  ② 消息填充（deviceId / productKey / deviceKey / messageId / timestamp）
  │  ③ 子设备会话 → 包装 ChildDeviceMessage（走网关代理）
  │  ④ 经网关取协议 codec → codec.encode() → EncodedMessage
  │  ⑤ session.send() → connection.sendMessage() → MQTT 下行 topic
  │  ⑥ replyRegistry.waitReply(messageId, 10s)   ← 等待设备回复（发生在设备所在节点）
  ▼
设备端收到指令 → 处理 → 上行 reply topic
  │
  ▼
codec.decode() → DefaultDecodedClientMessageHandler.handle()
  │  ⑦ MessageReply → replyRegistry.complete() 匹配 messageId → 完成等待
  ▼
调用方拿到回复内容（属性值 / 输出参数）→ 返回给页面
```

### 2.2 设计要点

1. **`DeviceMessageSender` 是接口** — 业务层只依赖接口，本地/集群实现按配置装配，业务无感知（集群路由见 [集群管理设计](./集群管理设计.md)）
2. **回复按 messageId 绑定** — 等待发生在设备所在节点本地；集群远程调用只需等任务返回
3. **超时默认 10s** — 与 [MQTT协议文档](./MQTT协议文档.md) 页面超时约定一致，可通过 `timeout` header 覆盖
4. **子设备走网关代理** — `LocalDeviceMessageSender` 检测 `ChildDeviceSession` 包装 `ChildDeviceMessage`，topic 由 `TopicMessageCodec.child` 递归拼接
5. **网关暴露协议编解码器** — `DeviceGateway` 增加 `getProtocolSupport()` 默认方法，下行编码统一经网关取协议
6. **单机/集群零切换成本** — 发送链路（LocalDeviceMessageSender）完全复用，集群只是入口多一层路由；单机部署不引入 Hazelcast

## 三、DeviceMessageSender 接口 + 本地实现

### 3.1 DeviceMessageSender（接口，sa-base）

`device/DeviceMessageSender.java`：

```java
/**
 * 设备消息下发服务接口 — 向设备下发命令并（可选）等待回复。
 * 实现：LocalDeviceMessageSender（单机）/ ClusterDeviceMessageSender（集群路由）。
 */
public interface DeviceMessageSender {

    /** 同步下发并等待回复 — 默认 10s 超时 */
    Mono<DeviceMessageReply> sendAndWait(String deviceId, DeviceMessage message);

    /** 同步下发并等待回复 — 自定义超时（毫秒），消息可带 timeout header 覆盖 */
    Mono<DeviceMessageReply> sendAndWait(String deviceId, DeviceMessage message, long timeout);

    /** 异步下发（async=true）— 不等待回复，返回 messageId */
    Mono<String> send(String deviceId, DeviceMessage message);
}
```

### 3.2 LocalDeviceMessageSender（本地实现，sa-base）

`device/support/LocalDeviceMessageSender.java` — 单机核心逻辑（即集群中"设备所在节点"执行的部分），依赖 `DeviceSessionManager`、`DeviceGatewayManager`、`DeviceCommandReplyRegistry`：

```java
public class LocalDeviceMessageSender implements DeviceMessageSender {

    private final DeviceSessionManager sessionManager;
    private final DeviceGatewayManager gatewayManager;
    private final DeviceCommandReplyRegistry replyRegistry;

    @Override
    public Mono<DeviceMessageReply> sendAndWait(String deviceId, DeviceMessage message, long timeout) {
        return sessionManager.getSession(deviceId, true)                 // ① 查会话（失效自动注销）
                .filter(DeviceSession::isAlive)                          // ② 在线判定
                .switchIfEmpty(Mono.error(new BusinessException("设备离线，无法下发命令")))
                .flatMap(session -> prepareMessage(session, message))    // ③ 填充 + 子设备包装
                .flatMap(msg -> doSend(session, msg)                     // ④⑤⑥ 编码 + 发送
                        .then(replyRegistry.waitReply(msg.getMessageId(), timeout)));  // ⑦ 等待回复
    }
}
```

**prepareMessage — 消息填充与子设备包装：**

```java
private Mono<DeviceMessage> prepareMessage(DeviceSession session, DeviceMessage message) {
    AbstractDeviceMessage msg = (AbstractDeviceMessage) message;
    // messageId / timestamp 填充（messageId 全局唯一，回复按它绑定）
    if (msg.getMessageId() == null) {
        msg.setMessageId(UUID.randomUUID().toString());
    }
    msg.setDeviceId(session.getDeviceId());
    msg.setProductKey(session.getProductKey());
    msg.setDeviceKey(session.getDeviceKey());

    // 子设备 → 包装为 ChildDeviceMessage（外层 = 网关 key，内层 = 子设备消息），
    // TopicMessageCodec.child 枚举自动拼接 /{gatewayPk}/{gatewayDk}/child/{childPk}/{childDk}/...
    if (session instanceof ChildDeviceSession) {
        ChildDeviceSession child = (ChildDeviceSession) session;
        DeviceSession parent = child.getParent();
        ChildDeviceMessage<DeviceMessage> wrapper =
                new ChildDeviceMessage<>(parent.getDeviceKey(),
                        child.getProductKey(), child.getDeviceKey(), msg);
        wrapper.setProductKey(parent.getProductKey());
        return Mono.just(wrapper);
    }
    return Mono.just(msg);
}
```

**doSend — 编码与发送：**

```java
private Mono<Void> doSend(DeviceSession session, DeviceMessage message) {
    // 子设备消息发往父（网关）会话的连接
    DeviceSession target = (session instanceof ChildDeviceSession)
            ? ((ChildDeviceSession) session).getParent() : session;

    return gatewayManager.getGateway(target.getGatewayId())          // 经网关取协议
            .flatMap(DeviceGateway::getProtocolSupport)
            .flatMap(ps -> ps.getMessageCodec(target.getTransport()))
            .flatMap(codec -> Mono.from(codec.encode(DefaultMessageEncodeContext.of(target, message))))
            .flatMap(target::send)                                    // 会话发送（见 3.4）
            .then();
}
```

> 说明：`MessageEncodeContext` 无默认实现，新建 `DefaultMessageEncodeContext`（参考 `FromDeviceMessageContext.of` 匿名类写法，携带 session/message，`reply()` 走默认空实现）。

### 3.3 DeviceCommandReplyRegistry（新建，sa-base）

`device/DeviceCommandReplyRegistry.java` — 回复注册表：发送时注册 `messageId → Sinks.One<DeviceMessageReply>`，设备回复到达时按 messageId 完成。**等待只发生在设备所在节点本地**，集群远程调用只需等任务返回。

```java
public class DeviceCommandReplyRegistry {

    private final Map<String, Sinks.One<DeviceMessageReply>> pending = new ConcurrentHashMap<>();

    /** 注册等待：超时后自动移除并报错（BusinessException "命令执行超时"） */
    public Mono<DeviceMessageReply> waitReply(String messageId, long timeout) {
        Sinks.One<DeviceMessageReply> sink = Sinks.one();
        pending.put(messageId, sink);
        return sink.asMono()
                .timeout(Duration.ofMillis(timeout), Mono.error(
                        new BusinessException("命令执行超时，设备未在 " + timeout + "ms 内回复")))
                .doFinally(ignore -> pending.remove(messageId));
    }

    /** 设备回复到达时调用 — 按 messageId 匹配并完成等待 */
    public void complete(DeviceMessageReply reply) {
        Sinks.One<DeviceMessageReply> sink = pending.remove(reply.getMessageId());
        if (sink != null) {
            sink.tryEmitValue(reply);
        }
    }
}
```

### 3.4 DeviceSession.send 落地

`DeviceSession` 接口增加发送方法（当前为注释预留），连接型会话实现，子设备会话防误用：

```java
// DeviceSession 接口（新增）
/** 发送已编码的消息给设备 */
Mono<Boolean> send(EncodedMessage encodedMessage);

// MqttConnectionSession（实现 — 转发到连接）
@Override
public Mono<Boolean> send(EncodedMessage encodedMessage) {
    if (!isAlive()) {
        return Mono.just(false);
    }
    return connection.sendMessage(encodedMessage).thenReturn(true);
}

// ChildDeviceSession（防误用 — 子设备消息必须经 DeviceMessageSender 包装后走父连接）
@Override
public Mono<Boolean> send(EncodedMessage encodedMessage) {
    return Mono.error(new UnsupportedOperationException(
            "子设备消息需经网关代理，请通过 DeviceMessageSender 下发"));
}
```

### 3.6 DefaultDecodedClientMessageHandler 补全

构造注入 `DeviceCommandReplyRegistry`，补全 Reply / 子设备消息处理：

```java
private final DeviceCommandReplyRegistry replyRegistry;

@Override
public Mono<Void> handle(Message message) {
    // ① Reply 类消息 → 匹配发送器的 pending 等待，完成调用方（messageId 绑定）
    if (message instanceof DeviceMessageReply) {
        replyRegistry.complete((DeviceMessageReply) message);
    }
    // ② 子设备消息 → 解包后发布内层消息（外层仅供路由，业务消费内层）
    if (message instanceof ChildDeviceMessage) {
        return eventBus.publishAsync(((ChildDeviceMessage<?>) message).getChildDeviceMessage());
    }
    if (message instanceof ChildDeviceMessageReply) {
        return eventBus.publishAsync(((ChildDeviceMessageReply<?>) message).getChildDeviceMessage());
    }
    // ③ 普通消息 → 发布到事件总线（回复消息同样发布，业务可监听）
    return eventBus.publishAsync(message);
}
```

## 四、集群发送（多节点部署）

多节点部署时，设备可能不在当前节点。发送链路不变，入口替换为集群路由实现：

```
DeviceService → ClusterDeviceMessageSender（持有 ClusterManager，通用设施）
  → ① registry.getConnectionServerId() 取设备所在节点（Redis，设备上线时写入）
  → ② 本地节点 → LocalDeviceMessageSender 直接发送
      远程节点 → clusterManager.getService(nodeId, DeviceMessageSender.class) 取代理
  → ③ 目标节点 LocalDeviceMessageSender 执行（本文档第三章全链路）
```

**本设计只做单机核心；通用集群设施（ClusterManager、节点管理、服务注册/获取、远程调用）见 [集群管理设计](./集群管理设计.md)，设备侧集群路由发送器（ClusterDeviceMessageSender）见该文档业务使用示例。**

## 五、业务层落地（sa-admin）

### 5.1 DeviceService 三方法实现

`DeviceService` 注入 `DeviceMessageSender` **接口**（不感知本地/集群），实现三个 TODO 方法：

```java
@Resource
private DeviceMessageSender messageSender;

/** 读取设备属性 — 同步下发，等待设备回复（默认 10s），返回属性值 */
public Map<String, Object> readProperties(String deviceId, List<String> properties) {
    ReadPropertyMessage message = new ReadPropertyMessage();
    message.setProperties(properties);
    ReadPropertyMessageReply reply = (ReadPropertyMessageReply)
            messageSender.sendAndWait(deviceId, message).block();
    // reply.isSuccess() == false → 抛 BusinessException(reply.getMessage())
    return reply.getProperties();
}

/** 设置设备属性 — 物模型校验后下发 */
public Map<String, Object> writeProperties(String deviceId, Map<String, Object> properties) {
    validateProperties(deviceId, properties);                 // 物模型校验（见六）
    WritePropertyMessage message = new WritePropertyMessage();
    message.setProperties(properties);
    WritePropertyMessageReply reply = (WritePropertyMessageReply)
            messageSender.sendAndWait(deviceId, message).block();
    return reply.getProperties();
}

/** 调用设备功能 — 物模型校验后下发 */
public Object invokeFunction(String deviceId, String functionId, Map<String, Object> params) {
    validateFunction(deviceId, functionId, params);           // 物模型校验（见六）
    FunctionInvokeMessage message = new FunctionInvokeMessage();
    message.setFunctionId(functionId);
    message.setInputs(params.entrySet().stream()
            .map(e -> new FunctionParameter(e.getKey(), e.getValue()))
            .collect(Collectors.toList()));
    FunctionInvokeMessageReply reply = (FunctionInvokeMessageReply)
            messageSender.sendAndWait(deviceId, message).block();
    return reply.getOutput();
}
```

> 说明：HTTP 接口需要同步返回结果，Service 层用 `.block()` 阻塞等待（项目已有先例：`MqttServerDeviceGateway.isChangeProtocol`）。Controller 接口签名保持不变，前端无需改动。

## 六、物模型校验（写属性 / 功能调用）

校验规则（通过 `registry.getDevice(deviceId) → getMetadata()` 获取物模型）：

| 场景 | 校验规则 |
|------|---------|
| 读属性 | 每个属性 ID 需在物模型中存在（`getPropertyOrNull`），否则报错 `属性 [xxx] 不存在` |
| 写属性 | ① 属性存在；② `accessMode` 非只读（只读属性不可写）；③ 值按 `DataType.validate()` 校验（int 范围 / bool / enum 枚举值等） |
| 功能调用 | ① 功能存在（`getFunctionOrNull`）；② 必填参数齐全（`FunctionParamMetadata.isRequired()`）；③ 每个参数按 `FunctionParamMetadata.getValueType().validate()` 校验 |

校验失败统一抛 `BusinessException`，由 `GlobalExceptionHandler` 转为错误响应，**不下发**。

## 七、子设备下行

子设备不持有连接，命令经网关代理：

```
LocalDeviceMessageSender（单机；集群时先路由到子设备所在节点 — 与直连设备同机制）
  → session = ChildDeviceSession（查子设备会话）
  → prepareMessage：包装 ChildDeviceMessage（外层=网关 key，内层=子设备命令）
  → TopicMessageCodec.child 编码 → /{gatewayPk}/{gatewayDk}/child/{childPk}/{childDk}/properties/write
  → 发往父（网关）会话的连接 → 网关转发给子设备
  → 子设备回复 → /{gatewayPk}/{gatewayDk}/child-reply/{childPk}/{childDk}/properties/write/reply
  → 解码为 ChildDeviceMessageReply → 内层 reply 的 messageId 与下行一致 → complete()
```

现有 `TopicMessageCodec` 的 `child`/`childReply` 枚举已完整支持上述 topic 的编解码，`MqttServerDeviceGateway.handleChildDeviceSession` 已支持子设备上线/下线会话管理，本设计只需补 `LocalDeviceMessageSender` 的包装逻辑。

## 九、异常与边界

| 场景 | 行为 |
|------|------|
| 设备离线（会话不存在 / !isAlive） | 报错 `设备离线，无法下发命令`，不下发 |
| 设备 10s 未回复 | `waitReply` 超时报错 `命令执行超时`（可用 `timeout` header 覆盖） |
| 设备回复 success=false | 返回设备回传的 code/message，页面提示失败原因 |
| 物模型校验失败 | 报具体错误（属性/功能不存在、参数类型错误），不下发 |
| 设备回复 messageId 与下行不一致 | pending 匹配不到，忽略（仅记日志），调用方仍走超时 |
| 异步下发（async header / `send()`） | 不注册 pending，返回 messageId 即成功 |
| 会话被新连接替换（设备重连） | pending 按 messageId 独立，不受影响 |
| 集群相关（设备所在节点不可用 / 节点退出 / 远程调用超时） | 见 [集群管理设计](./集群管理设计.md) 第九章 |

## 十一、验证方案

1. **编译**：`mvn compile -pl sa-base -o -q` 与 `mvn compile -pl sa-admin -o -q`
2. **单机下发联调**：设备连接（MQTTX 模拟，签名认证）→ 页面点击"读取属性"→ MQTTX 收到 `/{pk}/{dk}/properties/read` → 手动回复 `/{pk}/{dk}/properties/read/reply`（messageId 相同）→ 页面展示属性值
3. **写属性联调**：页面写入属性 → 设备收到 write 指令 → 回复 → 页面成功；物模型未定义的属性 → 页面直接报校验错误，设备收不到消息
4. **功能调用联调**：页面调用功能 → 设备收到 invoke → 回复 output → 页面展示结果
5. **超时验证**：设备不回复 → 10s 后页面提示"命令执行超时"
6. **离线验证**：设备断开后下发 → 页面提示"设备离线"
7. **子设备验证**：网关+子设备拓扑 → 向子设备下发 → 网关连接收到 `child/...` topic → 子设备经网关回复 → 页面拿到结果
8. **异步验证**：带 `async` header 下发 → 立即返回 messageId，不等待回复
9. **集群验证**：多节点部署相关（节点管理、服务注册/获取、远程下发、设备位置写入、故障转移）见 [集群管理设计](./集群管理设计.md) 第十一章
