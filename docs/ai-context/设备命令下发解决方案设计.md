# 设备命令下发解决方案设计（读属性 / 写属性 / 功能调用）

> 集群发送（多节点部署）的通用集群设施见 [集群管理设计](./集群管理设计.md)。本文档为单机核心设计，集群只是按配置替换发送器实现。

## 一、背景与现状

管理端需要向设备下发三类命令：**读取属性、写入属性、调用功能**。设备收到指令后需回复（MQTT 协议约定 10s 超时，见 [MQTT协议文档](./MQTT协议文档.md)）。

平台部署形态：**单机或集群**（集群时设备随机接入任一节点，会话为本地状态，下发的核心问题：**目标设备的会话可能不在当前节点**，需要集群转发 — 见集群设计文档）。

### 1.1 当前已具备的能力

| 能力 | 位置 | 说明 |
|------|------|------|
| 下行消息类 | `common/message/ReadPropertyMessage`、`WritePropertyMessage`、`FunctionInvokeMessage` | 均实现 `RepayableDeviceMessage<R>`（含 `newReply()` 回复骨架） |
| 回复消息类 | `ReadPropertyMessageReply`、`WritePropertyMessageReply`、`FunctionInvokeMessageReply` | 继承 `AbstractDeviceMessageReply`（success/code/message） |
| 下行 Topic 编码 | `common/topic/TopicMessageCodec` 枚举 | `readProperty`/`writeProperty`/`functionInvoke` 的 `:param` pattern 已定义；`buildTopicSegments()` 自动回填 productKey/deviceKey；子设备枚举递归拼接 `child` topic；入口 `TopicMessageCodec.encode(message) → TopicPayload(topic+payload)` |
| 协议编码器 | `sa-protocol/MqttDeviceMessageCodec.encode()` | Message → `DefaultMqttEncodedMessage`（QoS1），薄封装委托 TopicMessageCodec |
| 连接发送 | `VertxMqttConnection.sendMessage()` | `endpoint.publish()` 异步回调转 Mono，已实现 |
| 会话体系 | `MqttConnectionSession`（持有 connection + 烧录 key + protocolId + connectionServerId）、`ChildDeviceSession`（持有 parent + childKey） | `DeviceSessionManager.getSession(deviceId)` / `getSession(productKey, deviceKey)` / `getSession(deviceId, unregisterWhenNotAlive)`；`listenEvent()` 可监听会话注册/注销 |
| 网关管理 | `DeviceGatewayManager.getGateway(id)` | `MqttServerDeviceGateway` 持有 `Mono<ProtocolSupport>` |
| HTTP 入口 | `DeviceController` | `/device/{deviceId}/properties/read`、`/device/setting/{deviceId}/property`、`/device/invoked/{deviceId}/function/{functionId}` 三个接口已存在 |
| headers 约定 | [平台统一设备消息定义文档](./平台统一设备消息定义文档.md) + `common/message/Headers` 常量枚举 | 当前实现/消费 `async`（异步下发）、`timeout`（毫秒）2 个，其余 9 个平台文档已定义但未实现（见 2.3） |
| 物模型 | `ThingsMetadata.getPropertyOrNull/getFunctionOrNull`、`PropertyMetadata`（accessMode）、`FunctionMetadata`（inputs/isAsync/output）、`DataType.validate()` | 校验方法声明已预留（见六章，内部实现后续落地） |
| 连接服务器 ID | `DeviceField.CONNECTION_SERVER_ID` + `DefaultDeviceOperator.getConnectionServerId()` | 会话注册时写入（`DefaultDecodedClientMessageHandler.handleSessionEvent`），注销时清除（见 [集群管理设计](./集群管理设计.md)） |

### 1.2 当前缺口

| 缺口 | 现状 |
|------|------|
| 会话无发送能力 | `DeviceSession.send(EncodedMessage)` 是注释掉的预留 |
| 无下发门面 | `DeviceSendOperator` 不存在，业务层无法便捷下发三类命令 |
| 无统一下发入口 | `DeviceMessageSender` 不存在 |
| 无远程代理服务 | `DeviceMessageSendService` 不存在（集群远程节点代理接口） |
| 回复未处理 | `DefaultDecodedClientMessageHandler.handle()` 对回复消息是 TODO；`DeviceMessageReplyHandler` 接口不存在 |
| 业务层是桩 | `DeviceService.readProperties/writeProperties/invokeFunction` 均为 TODO 空实现 |
| 无超时等待机制 | 缺少 messageId → 回复的 pending 注册表 |
| 物模型校验未落地 | 校验方法已预留声明（空实现，见六章），参数校验/类型转换待后续实现（见 [物模型校验设计](./物模型校验设计.md)） |
| 子设备下行未打通 | 子设备命令需包装 `ChildDeviceMessage` 走网关代理，无实现 |
| 集群路由发送缺失 | `ClusterDeviceMessageSender` 不存在（通用集群设施见 [集群管理设计](./集群管理设计.md)） |

## 二、总体设计

### 2.1 分层架构

```
HTTP API（DeviceController 已有接口）
  │
  ▼
DeviceService（实现三个 TODO 方法）          ← sa-admin 业务层（校验在操作对象，见六章）
  │ 注入 DeviceSendOperator（不感知本地/集群）
  ▼
DeviceSendOperator（接口，实现 DefaultDeviceSendOperator） ← sa-base 下发门面
  │ 四个方法：send / readProperty / writeProperty / invokeFunction
  │ send: <R extends DeviceMessage> Mono<R> send(DeviceMessage message)，deviceId 取自消息
  │ readProperty() 等返回操作对象（ReadPropertySendOperation...），操作对象构造消息后回调 send()
  ▼
DeviceMessageSender（接口）                              ← sa-base 下发抽象
  ├── LocalDeviceMessageSender        — 本地实现（本节点会话直接下发）【本文档】
  └── ClusterDeviceMessageSender      — 集群路由实现（持有 ClusterManager：
        ① 取设备所在节点（Redis CONNECTION_SERVER_ID）
        ② 本地节点 → 直接走本地发送
        ③ 远程节点 → clusterManager.getService(nodeId, DeviceMessageSendService)
                     返回远程代理，代理经 Hazelcast 转发到目标节点执行）【见集群管理设计】
  ▼
LocalDeviceMessageSender（设备所在节点执行；同时实现 DeviceMessageReplyHandler）
  │  ① 查会话 + 在线判定（离线 → 报错）
  │  ② 消息填充（deviceId / productKey / deviceKey / messageId / timestamp）
  │  ③ 子设备会话 → 包装 ChildDeviceMessage（走网关代理）
  │  ④ 设备 Redis Hash 取 protocolId → 协议管理器取协议 → codec.encode() → EncodedMessage
  │  ⑤ session.send() → connection.sendMessage() → MQTT 下行 topic
  │  ⑥ waitReply(messageId, 10s)   ← 等待设备回复（发生在设备所在节点）
  ▼
设备端收到指令 → 处理 → 上行 reply topic
  │
  ▼
codec.decode() → DefaultDecodedClientMessageHandler.handle()
  │  ⑦ 回复消息 → DeviceMessageReplyHandler.onReply() 匹配 messageId → 完成等待
  ▼
调用方拿到回复内容（属性值 / 输出参数）→ 返回给页面
```

### 2.2 设计要点

1. **`DeviceSendOperator` 是下发门面** — 业务层只依赖它，`readProperty()/writeProperty()/invokeFunction()` 返回操作对象，操作对象构造消息（携带 deviceId）后统一回调 `DeviceSendOperator.send()` → `DeviceMessageSender`；send 返回 `Mono<R>`（`R extends DeviceMessage`，调用方按具体回复类型取用，如 `ReadPropertyMessageReply`；一次下发只等一个回复，用 Mono）
2. **`DeviceMessageSender` 是接口** — 本地/集群实现按配置装配，业务无感知（集群路由见 [集群管理设计](./集群管理设计.md)）
3. **`DeviceMessageSendService` 是远程代理接口** — 集群远程节点执行时创建代理（`clusterManager.getService(nodeId, DeviceMessageSendService)`），本节点实现（默认实现/匿名类）内部转发 `LocalDeviceMessageSender`；`ClusterDeviceMessageSender` 构造时注册本节点服务
4. **`DeviceMessageReplyHandler` 是回复处理接口** — 命名与消息接口 `common/message/DeviceMessageReply`（回复内容载体）区分，本接口是"回复处理者"；`LocalDeviceMessageSender` 同时实现 `DeviceMessageSender` + `DeviceMessageReplyHandler`，发送与回复处理内聚一体；解码后的回复消息经 `DefaultDecodedClientMessageHandler` 回调 `onReply()`；**子设备回复（`ChildDeviceMessageReply`）在 `onReply` 内解包后下发内层回复**（等待方是主动发起方，只需内层回复内容）；**事件总线发布保持外层原样**（监听器是被动消费方，需外层网关/子设备标识定位设备，见 3.5 / 3.8）
5. **回复按 messageId 绑定** — 等待发生在设备所在节点本地；集群远程调用只需等任务返回
6. **超时与异步经消息头控制** — 超时**以消息 `timeout` header 为准，恒有默认值不允许未设置**：`prepareMessage` 发送前回填 — 缺省填默认 10s（与 [MQTT协议文档](./MQTT协议文档.md) 页面超时约定一致），显式设置（调用方 header 或 `sendAndWait` 入参写入 header）则保留（见 3.5 `prepareMessage` / `resolveTimeout`）；**超时只约束同步下发的回复等待** — 异步下发（`send()`）不等待回复，无需超时；异步由物模型功能定义决定 — `FunctionMetadata.isAsync()` 为 true 时 `FunctionInvokeSendOperation` 自动补充 `async` header，发送器对带 `async` 的消息下发即成功、不等待回复
7. **子设备走网关代理** — `LocalDeviceMessageSender` 检测 `ChildDeviceSession` 包装 `ChildDeviceMessage`，topic 由 `TopicMessageCodec.child` 递归拼接
8. **协议经设备字段获取** — 下行编码先从设备（Redis Hash）取 `protocolId`（会话注册时写入），再从 `ProtocolSupportManager` 取协议 → codec，不依赖网关暴露
9. **单机/集群零切换成本** — 发送链路（LocalDeviceMessageSender）完全复用，集群只是入口多一层路由；单机部署不引入 Hazelcast

### 2.3 Headers — 消息头常量（`common/message/Headers.java`）

`Message.addHeader(String, Object)` 的头字段用常量枚举统一（与 [平台统一设备消息定义文档](./平台统一设备消息定义文档.md) 常用 Headers 约定一致）：

```java
/**
 * 设备消息头常量枚举 — 与平台统一设备消息定义文档的常用 Headers 约定一致。
 * 当前实现/消费的只有 ASYNC（下发即成功不等回复）与 TIMEOUT（超时覆盖），其余按需启用。
 */
public enum Headers {

    /** 是否异步，boolean 类型 — true 时下发即成功，不等待设备回复 */
    ASYNC("async"),

    /** 指定超时时间（毫秒）— 覆盖默认 10s 下发超时 */
    TIMEOUT("timeout");

    // 以下头字段平台文档已定义，当前未实现，按需启用：
    // /** 分片主消息 ID — 为下发消息的 messageId */  FRAG_MSG_ID("frag_msg_id"),
    // /** 分片总数 */                                FRAG_NUM("frag_num"),
    // /** 当前分片索引 */                            FRAG_PART("frag_part"),
    // /** 是否为最后一个分片 */                      FRAG_LAST("frag_last"),
    // /** 保持设备一直在线 — 与 DeviceOnlineMessage 配合 */            KEEP_ONLINE("keepOnline"),
    // /** 在线超时时间（秒） */                      KEEP_ONLINE_TIMEOUT_SECONDS("keepOnlineTimeoutSeconds"),
    // /** 不存储此消息数据 */                        IGNORE_STORAGE("ignoreStorage"),
    // /** 不记录此消息到日志 */                      IGNORE_LOG("ignoreLog"),
    // /** 合并最新属性数据 */                        MERGE_LATEST("mergeLatest");

    private final String value;

    Headers(String value) {
        this.value = value;
    }

    public String getValue() {
        return value;
    }
}
```

## 三、下发门面与本地实现

### 3.1 DeviceSendOperator（接口，sa-base）+ DefaultDeviceSendOperator

`device/DeviceSendOperator.java`：

```java
/**
 * 设备下发操作者 — 业务层下发门面，屏蔽底层发送器（本地/集群）。
 * 四个方法：send（通用下发，等待回复）、readProperty / writeProperty / invokeFunction（返回操作对象）。
 */
public interface DeviceSendOperator {

    /** 通用下发并等待回复 — deviceId 取自消息，默认 10s 超时，返回具体回复类型（调用方按 R 取用） */
    <R extends DeviceMessage> Mono<R> send(DeviceMessage message);

    /** 读属性操作对象 */
    ReadPropertySendOperation readProperty();

    /** 写属性操作对象 */
    WritePropertySendOperation writeProperty();

    /** 功能调用操作对象 */
    FunctionInvokeSendOperation invokeFunction();
}
```

`device/support/DefaultDeviceSendOperator.java`：

```java
/**
 * 设备下发操作者默认实现 — 持有 DeviceMessageSender（本地/集群按配置装配）+ DeviceRegistry（操作对象查物模型），
 * readProperty() 等返回操作对象，操作对象的 send() 回调本类的 send()。
 */
public class DefaultDeviceSendOperator implements DeviceSendOperator {

    private final DeviceMessageSender messageSender;
    private final DeviceRegistry registry;

    public DefaultDeviceSendOperator(DeviceMessageSender messageSender, DeviceRegistry registry) {
        this.messageSender = messageSender;
        this.registry = registry;
    }

    @Override
    @SuppressWarnings("unchecked")
    public <R extends DeviceMessage> Mono<R> send(DeviceMessage message) {
        // 回复按具体类型 R 转换返回（deviceId 由消息携带，发送器内部从消息取）
        return messageSender.sendAndWait(message)
                .map(reply -> (R) reply);
    }

    @Override
    public ReadPropertySendOperation readProperty() {
        // 操作对象 send() 前需查物模型校验，传入 registry
        return new ReadPropertySendOperation(this, registry);
    }

    @Override
    public WritePropertySendOperation writeProperty() {
        return new WritePropertySendOperation(this, registry);
    }

    @Override
    public FunctionInvokeSendOperation invokeFunction() {
        // 功能调用需查物模型（校验 + isAsync 决定 async header），传入 registry
        return new FunctionInvokeSendOperation(this, registry);
    }
}
```

### 3.2 SendOperation — 操作对象（读/写/调用）

三个操作对象结构同构：**send() 先取物模型校验（校验方法已预留声明、内部暂不实现，见第六章），校验通过后构造消息回调 `DeviceSendOperator.send()`**；只持操作者 + registry 引用，不持有发送器 — 发送链路统一收敛到 `DeviceSendOperator.send()` → `DeviceMessageSender`，避免分散。

`device/send/ReadPropertySendOperation.java`：

```java
/**
 * 读属性操作 — send() 先取物模型校验（属性存在性，校验在物模型内部，见第六章），
 * 再构造 ReadPropertyMessage 回调 DeviceSendOperator.send()。
 */
public class ReadPropertySendOperation {

    private final DeviceSendOperator operator;
    private final DeviceRegistry registry;

    public ReadPropertySendOperation(DeviceSendOperator operator, DeviceRegistry registry) {
        this.operator = operator;
        this.registry = registry;
    }

    /** 下发读属性并等待回复（属性值见 reply.getProperties()） */
    public Mono<ReadPropertyMessageReply> send(String deviceId, List<String> properties) {
        return registry.getDevice(deviceId)                    // ① 取物模型校验（物模型内部校验）
                .flatMap(DeviceOperator::getMetadata)
                .doOnNext(metadata -> checkErrors(metadata.validateReadProperties(properties)))
                .then(operator.send(buildMessage(deviceId, properties)));   // ② 校验通过 → 构造消息下发
    }

    private ReadPropertyMessage buildMessage(String deviceId, List<String> properties) {
        ReadPropertyMessage message = new ReadPropertyMessage();
        message.setDeviceId(deviceId);
        message.setProperties(properties);
        return message;
    }

    /** 校验失败（错误列表非空）→ 抛 BusinessException */
    private void checkErrors(List<String> errors) {
        if (CollUtil.isNotEmpty(errors)) {
            throw new BusinessException(String.join("; ", errors));
        }
    }
}
```

`device/send/WritePropertySendOperation.java`：

```java
/**
 * 写属性操作 — send() 先取物模型校验（属性存在 + 非只读 + 值合法，校验在物模型内部，见第六章），
```

`device/send/FunctionInvokeSendOperation.java` — 物模型功能定义了是否异步（`FunctionMetadata.isAsync()`），校验通过后按物模型补充 `async` header：

```java
/**
 * 功能调用操作 — send() 先取物模型校验（功能存在 + 参数名 + 必填 + 值合法，校验在物模型内部，见第六章），
 * 构造 FunctionInvokeMessage 后回调 DeviceSendOperator.send()；物模型功能 isAsync=true 时自动补充 async header（下发即成功，不等回复）。
 */
public class FunctionInvokeSendOperation {

    private final DeviceSendOperator operator;
    private final DeviceRegistry registry;

    public FunctionInvokeSendOperation(DeviceSendOperator operator, DeviceRegistry registry) {
        this.operator = operator;
        this.registry = registry;
    }

    /** 下发功能调用并等待回复（异步功能自动补充 async header，下发即成功） */
    public Mono<FunctionInvokeMessageReply> send(String deviceId, String functionId, Map<String, Object> params) {
        return registry.getDevice(deviceId)
                .flatMap(DeviceOperator::getMetadata)
                .doOnNext(metadata -> checkErrors(metadata.validateFunction(functionId, params)))   // ① 校验（物模型内部）
                .flatMap(metadata -> {
                    FunctionInvokeMessage message = buildMessage(deviceId, functionId, params);
                    // ② 物模型功能 isAsync=true → 补充 async header
                    if (metadata.getFunctionOrNull(functionId).isAsync()) {
                        message.addHeader(Headers.ASYNC.getValue(), true);
                    }
                    return operator.send(message);
                });
    }

    private FunctionInvokeMessage buildMessage(String deviceId, String functionId, Map<String, Object> params) {
        FunctionInvokeMessage message = new FunctionInvokeMessage();
        message.setDeviceId(deviceId);
        message.setFunctionId(functionId);
        message.setInputs(buildInputs(params));        // inputs 逐参数包装 FunctionParameter
        return message;
    }

    /** 校验失败（错误列表非空）→ 抛 BusinessException */
    private void checkErrors(List<String> errors) {
        if (CollUtil.isNotEmpty(errors)) {
            throw new BusinessException(String.join("; ", errors));
        }
    }
}
```

### 3.3 DeviceMessageSender（接口，sa-base）

`device/DeviceMessageSender.java`：

```java
/**
 * 设备消息发送服务接口 — 向设备下发命令并（可选）等待回复。
 * 实现：LocalDeviceMessageSender（单机）/ ClusterDeviceMessageSender（集群路由）。
 */
public interface DeviceMessageSender {

    /** 默认下发超时（毫秒）— 消息缺省 timeout header 时，prepareMessage 发送前回填此值（10s 与 MQTT 协议约定一致） */
    long DEFAULT_TIMEOUT_MS = 10_000L;

    /** 同步下发并等待回复 — 超时以消息 timeout header 为准（缺省由 prepareMessage 回填默认 10s，不允许未设置），deviceId 取自消息 */
    default Mono<DeviceMessageReply> sendAndWait(DeviceMessage message) {
        return sendAndWait(message, DEFAULT_TIMEOUT_MS);
    }

    /** 同步下发并等待回复 — 自定义超时（毫秒）：正值时写入消息 timeout header，按 header 等待（调用方已设置的 header 优先，最终以 header 为准） */
    Mono<DeviceMessageReply> sendAndWait(DeviceMessage message, long timeout);

    /** 异步下发（async=true）— 不等待回复，下发即成功，无需超时 */
    Mono<Void> send(DeviceMessage message);
}
```

### 3.4 DeviceMessageReplyHandler（接口，sa-base）

`device/DeviceMessageReplyHandler.java` — 回复处理接口，与消息接口 `common/message/DeviceMessageReply`（回复内容载体）区分：**本接口是"回复处理者"**，消息接口是"回复内容载体"。

```java
/**
 * 设备回复处理接口 — 设备回复消息到达时的回调（按 messageId 匹配发送时的 pending 等待；

public interface DeviceMessageReplyHandler {

    /** 处理设备回复消息 — 按 messageId 匹配并完成等待的调用方 */
```

### 3.5 LocalDeviceMessageSender（本地实现，sa-base）

`device/support/LocalDeviceMessageSender.java` — 单机核心逻辑（即集群中"设备所在节点"执行的部分），**同时实现 `DeviceMessageSender` + `DeviceMessageReplyHandler`**（发送与回复处理内聚一体），依赖 `DeviceSessionManager`、`DeviceRegistry`、`ProtocolSupportManager`：

```java
public class LocalDeviceMessageSender implements DeviceMessageSender, DeviceMessageReplyHandler {

    /** messageId → 回复等待（发送时注册，回复到达时完成） */
    private final Map<String, Sinks.One<DeviceMessageReply>> pending = new ConcurrentHashMap<>();

    private final DeviceSessionManager sessionManager;
    private final DeviceRegistry registry;
    private final ProtocolSupportManager protocolSupportManager;

    @Override
    public Mono<DeviceMessageReply> sendAndWait(DeviceMessage message, long timeout) {
        // 显式超时写入 header（addHeaderIfAbsent — 调用方已设置的 header 优先）— 等待以 header 为准；
        // prepareMessage 对仍缺省的消息回填默认 10s（不允许没有超时）
        if (timeout > 0) {
            message.addHeaderIfAbsent(Headers.TIMEOUT.getValue(), timeout);
        }
        // deviceId 由消息携带（所有具体消息均为 AbstractDeviceMessage）
        return sessionManager.getSession(((AbstractDeviceMessage) message).getDeviceId(), true)   // ① 查会话（失效自动注销）
                .filter(DeviceSession::isAlive)                          // ② 在线判定
                .switchIfEmpty(Mono.error(new BusinessException("设备离线，无法下发命令")))
                .flatMap(session -> prepareMessage(session, message))    // ③ 填充 + 默认超时回填 + 子设备包装
                .flatMap(msg -> {
                    // ④ 发送前先注册 pending（设备可能秒回：回复在 doSend 完成前到达也能经 onReply 命中 sink，
                    //    Sinks.One 无订阅时缓存值 — 不丢回复）；生效超时以 header 为准（prepareMessage 已保证恒有值）
                    Mono<DeviceMessageReply> replyMono = isAsync(msg)
                            ? Mono.just((DeviceMessageReply) ((RepayableDeviceMessage<?>) msg).newReply())  // async：下发即成功，返回空回复骨架
                            : waitReply(msg.getMessageId(), resolveTimeout(msg));                            // 等待设备回复
                    // ⑤ 编码 + 发送 → 等待回复；⑥ 无论成功 / 失败 / 超时 / 取消 → doFinally 移除 pending（防内存遗留）
                    return doSend(session, msg)
                            .then(replyMono)
                            .doFinally(ignore -> pending.remove(msg.getMessageId()));
                });
    }

    /** 生效超时 — 以消息 timeout header 为准（prepareMessage 已回填默认 10s，恒有值）；非法值兜底默认 10s */
    private long resolveTimeout(DeviceMessage message) {
        Object header = message.getHeaderOrElse(Headers.TIMEOUT.getValue(), () -> DEFAULT_TIMEOUT_MS);
        return header instanceof Number && ((Number) header).longValue() > 0
                ? ((Number) header).longValue() : DEFAULT_TIMEOUT_MS;
    }

    @Override
    public Mono<Void> send(DeviceMessage message) {
        return sessionManager.getSession(((AbstractDeviceMessage) message).getDeviceId(), true)
                .filter(DeviceSession::isAlive)
                .switchIfEmpty(Mono.error(new BusinessException("设备离线，无法下发命令")))
                .flatMap(session -> prepareMessage(session, message))
                .flatMap(msg -> doSend(session, msg));   // 异步：不等待回复，下发即成功，无需超时
    }

    /** async header 判定 — 带 async=true 的消息下发即成功，不等待回复（功能调用的物模型 isAsync 自动补充，见 3.2） */
    private boolean isAsync(DeviceMessage message) {
        return Boolean.TRUE.equals(message.getHeaderOrElse(Headers.ASYNC.getValue(), () -> Boolean.FALSE));
    }

    /** ⑦ 设备回复到达 → 按 messageId 匹配并完成等待（DeviceMessageReplyHandler 接口实现） */
    @Override
    public void onReply(AbstractDeviceMessageReply reply) {
        // 子设备回复解包 — 等待方（sendAndWait 调用方）是主动发起方，已知道下发目标设备，只需内层回复内容；
        // 解包后按内层回复匹配/下发（外层 messageId = 内层回复 messageId，见十章 ChildDeviceMessageReply 改造）；
        // 父类信息（网关/子设备标识）保留在事件总线发布路径 — handler ② 按外层发布，监听器自行解包
        AbstractDeviceMessageReply target = reply;
        if (reply instanceof ChildDeviceMessageReply) {
            target = ((ChildDeviceMessageReply<?>) reply).getChildDeviceMessage();
        }
        Sinks.One<DeviceMessageReply> sink = pending.remove(target.getMessageId());
        if (sink != null) {
            sink.tryEmitValue(target);
        }
    }

    /**
     * 注册等待 — 在【发送前】注册（回复可能在消息发出后立刻到达，注册必须早于 doSend；
     * Sinks.One 无订阅时缓存值，回复到达即命中 sink，不丢失）。
     * 清理由 sendAndWait 外层 doFinally 兜底（见上）：doSend 失败 / 超时 / 调用方取消 / 正常完成均移除条目，防内存遗留。
     */
    private Mono<DeviceMessageReply> waitReply(String messageId, long timeout) {
        Sinks.One<DeviceMessageReply> sink = Sinks.one();
        pending.put(messageId, sink);
        return sink.asMono()
                .timeout(Duration.ofMillis(timeout), Mono.error(
                        new BusinessException("命令执行超时，设备未在 " + timeout + "ms 内回复")));
    }
}
```

**prepareMessage — 消息填充与子设备包装：**

```java
private Mono<DeviceMessage> prepareMessage(DeviceSession session, DeviceMessage message) {
    AbstractDeviceMessage msg = (AbstractDeviceMessage) message;
    // messageId / timestamp 填充（messageId 全局唯一，回复按它绑定）
    if (msg.getMessageId() == null) {
        msg.setMessageId(UUID.randomUUID().toString());
    }
    msg.setDeviceId(session.getDeviceId());
    msg.setProductKey(session.getProductKey());
    msg.setDeviceKey(session.getDeviceKey());
    // 默认超时回填 — 每个消息发送前必须有 timeout header（缺省 10s，不允许未设置），等待/发送以 header 为准
    msg.addHeaderIfAbsent(Headers.TIMEOUT.getValue(), DEFAULT_TIMEOUT_MS);

    // 子设备 → 包装为 ChildDeviceMessage（外层 = 网关三元信息，内层 = 子设备消息），
    // TopicMessageCodec.child 枚举自动拼接 /{gatewayPk}/{gatewayDk}/child/{childPk}/{childDk}/...
    if (session instanceof ChildDeviceSession) {
        ChildDeviceSession child = (ChildDeviceSession) session;
        DeviceSession parent = child.getParent();
        // 构造只传父（网关）设备 id / deviceKey / productKey；子设备三元信息由内层消息携带（上方已填充 session 即子设备三元），
        // 外层与内层是同一条消息，外层 messageId 取内层 messageId（构造内设置，回复按它绑定）
        ChildDeviceMessage<DeviceMessage> wrapper =
                new ChildDeviceMessage<>(parent.getDeviceId(), parent.getDeviceKey(), parent.getProductKey(), msg);
        return Mono.just(wrapper);
    }
    return Mono.just(msg);
}
```

**doSend — 编码与发送：**

```java
private Mono<Void> doSend(DeviceSession session, DeviceMessage message) {
    // 子设备消息发往父（网关）会话的连接（子设备与父设备同协议，取父设备的 protocolId）
    DeviceSession target = (session instanceof ChildDeviceSession)
            ? ((ChildDeviceSession) session).getParent() : session;

    return registry.getDevice(target.getDeviceId())                       // ① 设备 Redis Hash 取 protocolId（会话注册时写入）
            .flatMap(operator -> operator.getSelfConfig(DeviceField.PROTOCOL_ID.getValue()))
            .map(Value::asString)
            .filter(StringUtils::isNotEmpty)
            .switchIfEmpty(Mono.error(new BusinessException("设备未绑定协议，无法下发")))
            .flatMap(protocolSupportManager::getProtocol)                  // ② 协议管理器取协议（ProtocolSupportManager）
            .flatMap(ps -> ps.getMessageCodec(target.getTransport()))
            .flatMap(codec -> Mono.from(codec.encode(DefaultMessageEncodeContext.of(target, message))))
            .flatMap(target::send)                                        // 会话发送（见 3.6）
            .then();
}
```

> 说明：`MessageEncodeContext` 无默认实现，新建 `DefaultMessageEncodeContext`（参考 `FromDeviceMessageContext.of` 匿名类写法，携带 session/message，`reply()` 走默认空实现）。依赖 import：`org.apache.commons.lang3.StringUtils`、`module/support/cache/core/Value`。

### 4.3 ClusterDeviceMessageSender — 集群路由实现

`device/support/ClusterDeviceMessageSender.java`：

```java
/**
 * 集群路由发送器 — 设备可能不在本节点：
 * ① Redis CONNECTION_SERVER_ID 取设备所在节点
 * ② 本地节点 → LocalDeviceMessageSender 直接发送
 * ③ 远程节点 → clusterManager.getService(nodeId, DeviceMessageSendService) 远程代理，经 Hazelcast 转发到目标节点执行
 * 构造时注册本节点的 DeviceMessageSendService（其他节点经集群代理调用本节点设备发送）。
 */
public class ClusterDeviceMessageSender implements DeviceMessageSender {

    private final ClusterManager clusterManager;
    private final LocalDeviceMessageSender localSender;
    private final DeviceRegistry registry;

    public ClusterDeviceMessageSender(ClusterManager clusterManager,
                                      LocalDeviceMessageSender localSender,
                                      DeviceRegistry registry) {
        this.clusterManager = clusterManager;
        this.localSender = localSender;
        this.registry = registry;
        // 注册本节点远程发送服务 — 其他节点 getService(nodeId, DeviceMessageSendService) 可调用本节点设备
        clusterManager.register(DeviceMessageSendService.class, new DefaultDeviceMessageSendService(localSender));
    }

    @Override
    public Mono<DeviceMessageReply> sendAndWait(DeviceMessage message, long timeout) {
        return getDeviceNodeId(((AbstractDeviceMessage) message).getDeviceId())   // ① 设备所在节点
                .flatMap(nodeId -> {
                    if (nodeId.equals(clusterManager.getCurrentNodeId())) {        // ② 本节点
                        return localSender.sendAndWait(message, timeout);
                    }
                    // ③ 远程节点 → 代理调用（目标节点 DefaultDeviceMessageSendService → LocalDeviceMessageSender）
                    return clusterManager.getService(nodeId, DeviceMessageSendService.class)
                            .switchIfEmpty(Mono.error(new BusinessException("目标节点未注册发送服务: " + nodeId)))
                            .flatMap(service -> service.sendAndWait(message, timeout));
                });
    }

    @Override
    public Mono<Void> send(DeviceMessage message) {
        return getDeviceNodeId(((AbstractDeviceMessage) message).getDeviceId())
                .flatMap(nodeId -> {
                    if (nodeId.equals(clusterManager.getCurrentNodeId())) {
                        return localSender.send(message);
                    }
                    // 异步下发远程执行：目标节点只发不等回复，本节点直接返回（回复不跨节点回传）
                    return clusterManager.getService(nodeId, DeviceMessageSendService.class)
                            .switchIfEmpty(Mono.error(new BusinessException("目标节点未注册发送服务: " + nodeId)))
                            .flatMap(service -> service.send(message));
                });
    }

    /**
     * 设备所在节点 ID — Redis CONNECTION_SERVER_ID（会话注册时写入，注销时清除）。
     * 兜底：设备刚连接/上线瞬时，会话已在本节点注册但 Redis 字段尚未写入 — 取不到节点 ID 时查本节点会话：
     * 在线（该窗口内设备必然在本节点）→ 本节点下发；本节点也无会话 → 设备未在线，明确报错（不静默丢弃）
     */
    private Mono<String> getDeviceNodeId(String deviceId) {
        return registry.getDevice(deviceId)
                .flatMap(DeviceOperator::getConnectionServerId)
                .filter(StringUtils::isNotEmpty)
                .switchIfEmpty(sessionManager.getSession(deviceId, true)
                        .filter(DeviceSession::isAlive)
                        .map(session -> clusterManager.getCurrentNodeId())
                        .switchIfEmpty(Mono.error(new BusinessException("设备未在线，无法下发命令"))));
    }
}
```

> 说明：设备离线时 `CONNECTION_SERVER_ID` 已被会话注销清除，且本节点查无会话 → 明确报"设备未在线，无法下发命令"；设备刚连接/上线瞬时（会话已在本节点注册、Redis 字段尚未写入）→ 判为本节点下发，正常发送不误报。

## 七、子设备下行

子设备不持有连接，命令经网关代理：

```
DeviceSendOperator → DeviceMessageSender（单机：LocalDeviceMessageSender；集群：先路由到子设备所在节点 — 与直连设备同机制）
  → session = ChildDeviceSession（查子设备会话）
  → prepareMessage：包装 ChildDeviceMessage（外层=网关 key，内层=子设备命令）
  → TopicMessageCodec.child 编码 → /{gatewayPk}/{gatewayDk}/child/{childPk}/{childDk}/properties/write
  → 发往父（网关）会话的连接 → 网关转发给子设备
  → 子设备回复 → /{gatewayPk}/{gatewayDk}/child-reply/{childPk}/{childDk}/properties/write/reply
  → 解码为 ChildDeviceMessageReply → DefaultDecodedClientMessageHandler 回调 onReply()（解包内层回复，按内层 messageId 命中 pending 完成等待 — 等待方拿内层回复类型）→ 外层包装原样发布事件总线（保留父类信息，监听器自行解包）
```

现有 `TopicMessageCodec` 的 `child`/`childReply` 枚举已完整支持上述 topic 的编解码，`MqttServerDeviceGateway.handleChildDeviceSession` 已支持子设备上线/下线会话管理，本设计只需补 `LocalDeviceMessageSender` 的包装逻辑。

## 九、异常与边界

| 场景 | 行为 |
|------|------|
| 设备离线（会话不存在 / !isAlive） | 报错 `设备离线，无法下发命令`，不下发 |
| 设备 10s 未回复 | `waitReply` 超时报错 `命令执行超时`（`timeout` header 可覆盖）；pending 条目经外层 `doFinally` 移除，防内存遗留 |
| 超时未设置 / 非法 | `prepareMessage` 发送前回填默认 10s（`addHeaderIfAbsent`，`DEFAULT_TIMEOUT_MS`）— 以 header 为准，`waitReply` 恒有正超时值，不允许没有超时 |
| 设备秒回（回复在 doSend 完成前到达） | pending 已**发送前注册**，`onReply` 命中 sink（`Sinks.One` 无订阅时缓存值，订阅后立即下发）— 不丢回复 |
| 下发编码/发送失败（doSend 异常） | 已注册的 pending 条目经外层 `doFinally` 移除（发送前已注册，失败同样清理），无遗留 |
| 设备回复 success=false | 返回设备回传的 code/message，页面提示失败原因 |
| 物模型校验失败（校验落地后生效 — 本阶段校验方法为空实现恒通过） | 报具体错误（属性/功能不存在、参数类型错误），不下发 |
| 设备回复 messageId 与下行不一致 | pending 匹配不到，忽略（仅记日志），调用方仍走超时 |
| 子设备回复（`ChildDeviceMessageReply`） | `onReply` 解包内层回复后按内层 messageId 完成等待（等待方拿到内层回复类型）；事件总线发布保持外层原样 — 保留网关/子设备标识等父类信息，监听器自行 `getChildDeviceMessage()` 取内层回复 |
| 异步下发（async header / `send()`） | 不注册 pending，下发即成功（`sendAndWait` 对 async 消息返回空回复骨架，不等待设备回复）；`send()` 的编码 + 发送同样受默认超时约束（10s，header 可覆盖），不允许无限挂起 |
| 会话被新连接替换（设备重连） | pending 按 messageId 独立，不受影响 |
| 集群：设备所在节点不可用 / 节点退出 | `getService` 失败或代理调用报 `目标节点不可用`（见 [集群管理设计](./集群管理设计.md) 第九章） |
| 集群：目标节点未注册发送服务 | `getService(nodeId, DeviceMessageSendService)` 返回 empty → 报 `目标节点未注册发送服务` |

## 十一、验证方案

1. **编译**：`mvn compile -pl sa-base -o -q` 与 `mvn compile -pl sa-admin -o -q`
2. **单机下发联调**：设备连接（MQTTX 模拟，签名认证）→ 页面点击"读取属性"→ MQTTX 收到 `/{pk}/{dk}/properties/read` → 手动回复 `/{pk}/{dk}/properties/read/reply`（messageId 相同，**payload 必须带 `"success": true`**，协议文档 3.2 上行回复格式）→ 页面展示属性值
   - ⚠️ 回复 payload 缺 `success` 字段时：Jackson 反序列化 `success` 保持默认 `false`，平台判定为失败回复 → 抛 `BusinessException`（message 为空 → 兜底文案"设备执行失败，请检查设备回复"，见 DeviceService.replyError）→ 页面提示失败而不是展示属性值
3. **写属性联调**：页面写入属性 → 设备收到 write 指令 → 回复 → 页面成功（本阶段校验方法为空实现恒通过；校验落地后：物模型未定义的属性 → 页面报校验错误，设备收不到消息）
4. **功能调用联调**：页面调用功能 → 设备收到 invoke → 回复 output → 页面展示结果
5. **超时验证**：设备不回复 → 10s 后页面提示"命令执行超时"
6. **离线验证**：设备断开后下发 → 页面提示"设备离线"
7. **子设备验证**：网关+子设备拓扑 → 向子设备下发 → 网关连接收到 `child/...` topic → 子设备经网关回复 → 页面拿到结果
8. **异步验证**：带 `async` header 下发 → 立即返回 messageId，不等待回复
9. **集群验证**：多节点部署相关（节点管理、服务注册/获取、远程下发、设备位置写入、故障转移）见 [集群管理设计](./集群管理设计.md) 第十一章
